# AI Chat Widget (в стиле Jivo) + Gemini на backend

Фронтенд чата ИИ-агента: плавающий виджет в правом нижнем углу и демонстрационная
страница магазина автозапчастей, на которой он виден в контексте. Ответы на вопросы
пользователя генерирует **Gemini API** на стороне backend; если Gemini недоступен,
чат автоматически переходит на мок-ответы и продолжает работать.

Агент отвечает **только на вопросы про товары для автомобилей** (подбор, наличие,
цена, доставка, оплата, возврат, гарантия товара). Любой другой вопрос — про ремонт,
диагностику, установку, запись в сервис и посторонние темы — он не разбирает,
а перенаправляет клиента на телефон автомастерской.

## Как запустить

```bash
npm install
cp .env.example .env      # Windows: copy .env.example .env
# впишите GEMINI_API_KEY в .env (ключ: https://aistudio.google.com/apikey)
npm start
```

Затем откройте http://localhost:5173

Проверить, что ключ и модель работают:

```bash
npm run check:gemini
```

Без ключа всё тоже работает — просто на мок-ответах.

## Деплой на Vercel

Проект готов к Vercel: статика (`index.html`, `styles/`, `src/`) отдаётся как есть,
а backend выполняется как serverless-функции в `api/`.

```bash
npm i -g vercel     # если CLI ещё не установлен
vercel login        # или: vercel deploy --token <TOKEN>
vercel deploy --prod
```

Что нужно настроить в проекте Vercel:

- **Environment Variables** → `GEMINI_API_KEY` (и при желании `GEMINI_MODEL`,
  `GEMINI_TRANSPORT`, `GEMINI_TIMEOUT_MS`). Без ключа функции отдают мок-ответы.
- Файл `.env` в деплой не попадает (см. `.vercelignore`) — ключ задаётся только
  в настройках проекта.
- `api/chat.js` (`POST /api/chat`) и `api/health.js` (`GET /api/health`) повторяют
  контракт локального `server/index.js`, поэтому фронтенд работает без изменений.
- Функции stateless: история диалога приходит от клиента полем `history`.

## Как устроены ответы

```
Клиент (виджет)                    Backend (Express)                 Gemini
────────────────                   ─────────────────                 ──────
вопрос пользователя  ──POST /api/chat──▶  system instruction  ──▶  generateContent
                     ◀──{reply, quickReplies}──                        │
                                                                      ▼
                        нет ключа / ошибка / таймаут →  мок-ответ из src/mock/mockChat.js
```

- Ключ Gemini живёт только в `.env` на сервере и в браузер не попадает;
  `.env`, `server/` и `package.json` не отдаются статикой (проверено: 404).
- Ответ модели приводится к контракту `{reply, quickReplies}`; если ответ пришёл
  обрезанным или с лишним текстом вокруг JSON, поля вытаскиваются спасением
  (см. `parseReply` в `server/gemini.js`).
- Память диалога: клиент присылает историю, а для транспорта `interactions`
  сервер дополнительно использует `previous_interaction_id` (см. `sessionId`).
- Два транспорта Gemini (`GEMINI_TRANSPORT`): `generate-content`
  (`/v1beta/models/{model}:generateContent`) и `interactions` (`/v1beta/interactions`).
  В режиме `auto` начинаем с первого, при ошибке API (400/403/404/429/5xx)
  один раз пробуем второй и запоминаем рабочий.
- Быстрые ответы под лентой приходят из `quickReplies` модели; если Gemini
  молчит — из мок-базы знаний.

## О чём агент отвечает, а о чём нет

Правило задано в мок-данных (`src/mock/mockChat.js`) и повторяется в системной
инструкции для Gemini (`server/prompt.js`), поэтому и живые ответы, и мок-режим
ведут себя одинаково.

| Вопрос | Что делает агент |
| --- | --- |
| Подбор, совместимость (VIN/марка/модель), характеристики | отвечает сам |
| Наличие, цена, скидки, валюта цен | отвечает сам |
| Доставка, оплата, возврат и гарантия **товара** | отвечает сам |
| Ремонт, диагностика, СТО, установка, замена, шиномонтаж, запись | перенаправляет в автомастерскую по телефону |
| Любая посторонняя тема (погода, фильмы и т. п.) | перенаправляет в автомастерскую по телефону |

- Телефон и часы автомастерской лежат в `mockWorkshop` (`mockShop` — сам магазин,
  `mockAgent` — профиль агента). Оттуда же телефон подставляется в шапку страницы
  и в блок «Вопросы ассистенту» через `renderContacts()` в `src/app.js`.
- В мок-режиме перенаправление возвращается флагом `redirect: true`
  (`mockFallback` и правило `kb-workshop`), а сам текст ответа собирает
  `redirectToWorkshop()`.
- Чтобы поменять телефон автомастерской — достаточно `mockWorkshop.phone`
  и `mockWorkshop.phoneHref` в `src/mock/mockChat.js`.

Проверка правила:

```bash
npm run test:agent
```

## Цены и валюты

Цены товаров заданы в одной базовой валюте (`mockBaseCurrency` — рубль), а показываются
в трёх: **₽ рубли**, **сум узбекские сумы**, **$ доллары США**. Переключатель — над
сеткой товаров в каталоге, рядом подпись с курсами; выбор сохраняется в `localStorage`.

- Курсы — мок-данные: `src/mock/mockCurrency.js` (`// TODO: заменить на реальные данные`).
  Сейчас: 1 ₽ ≈ 143,5 сум и 1 $ ≈ 88,5 ₽.
- Пересчёт и форматирование — `src/currency.js` (умеет округлять сумы до 1000 и
  ставить символ до/после числа). Модуль универсальный: тот же код работает в Node,
  поэтому сервер отвечает теми же числами, что и витрина.
- Выбранная валюта уходит в `POST /api/chat` полем `currency`, попадает в системную
  инструкцию Gemini (`server/prompt.js`) — ассистент называет стоимость в той же валюте.
  В мок-режиме ответы (`kb-price`, `kb-currency`) тоже содержат все три валюты.

Проверка цен и пересчёта:

```bash
npm run test:currency
```

### Если в чате мок-ответы вместо Gemini

Смотрите подпись под полем ввода («Работает на Gemini …» / «мок-данных») и лог сервера:

| Симптом в логе | Причина | Что делать |
| --- | --- | --- |
| `GEMINI_API_KEY не задан` | ключа нет | впишите ключ в `.env`, перезапустите |
| `Gemini 429: exceeded a quota` | исчерпана квота проекта | проверьте лимиты: https://ai.dev/rate-limit |
| `Gemini 503: high demand` | временная перегрузка модели | повторите запрос, попробуйте другую `GEMINI_MODEL` |
| `превышено время ожидания` | модель не ответила в `GEMINI_TIMEOUT_MS` | увеличьте лимит или смените модель |

Диагностика той же ошибки вне сервера:

```bash
npm run check:gemini
npm run check:gemini -- --transport=interactions
```

## Возможности виджета

- Круглая кнопка-лаунчер с пульсацией и счётчиком непрочитанных.
- Окно чата: шапка с аватаром и статусом агента, сворачивание и закрытие.
- Лента сообщений с аватарами, временем и статусами доставки (✓ / ✓✓).
- Индикатор набора текста («печатает…»), пока ждём ответ Gemini.
- Быстрые ответы (чипы) под лентой и внутри сообщений.
- Поле ввода с автоувеличением, отправка по Enter (Shift+Enter — перенос строки).
- Панель эмодзи и прикрепление файлов.
- Звуковой сигнал на ответ агента (можно выключить кнопкой в шапке).
- Автооткрытие «приглашения» через 9 секунд (имитация Jivo).
- Мобильная раскладка: на узких экранах чат разворачивается на весь экран.

Наведите курсор на сообщение агента — во всплывающей подсказке видно, отвечал
Gemini или мок-логика.

## Мок-данные

По правилу проекта (`AGENTS.md`) все временные данные вынесены в отдельный слой —
`src/mock/mockChat.js` (чат и каталог) и `src/mock/mockCurrency.js` (курсы валют) —
и помечены `// TODO: заменить на реальные данные`.
Модули универсальные: подключаются и в браузере (`window.ChatMocks`), и в Node
(`require()` из `server/`), поэтому мок-ответ один и тот же на клиенте и сервере.

Что там лежит:

- `mockAgent`, `mockShop`, `mockWorkshop` — профили агента, магазина и автомастерской
  (телефон для перенаправления);
- `mockMessages` — приветственная лента;
- `mockQuickReplies` — быстрые ответы;
- `mockKnowledgeBase` + `mockFallback` + `matchIntent()`/`mockReply()` — «мозг»
  ассистента в мок-режиме (подбор ответа по ключевым словам;
  элементы с `redirect: true` уводят в автомастерскую);
- `mockEmojis`, `mockAttachments` — панель эмодзи и файлы;
- `mockProducts`, `mockFeatures`, `mockStats`, `mockNav` — контент демо-страницы;
- `mockCurrencies`, `mockExchangeRates`, `mockRates` — валюты и курсы для цен.

Чтобы подменить данные — отредактируйте только файлы в `src/mock/`. Когда появится
реальная база знаний магазина, обновите `server/prompt.js` (там же собирается
системная инструкция для Gemini).

## API

`POST /api/chat`

```jsonc
// запрос
{
  "sessionId": "sess-...",
  "message": "Сколько стоят колодки на Camry 2019 в сумах?",
  "history": [{ "author": "user", "text": "..." }],
  "currency": "UZS"          // валюта цен, выбранная на витрине: RUB | UZS | USD
}
// ответ
{ "reply": "…", "quickReplies": ["…"], "source": "gemini", "model": "gemini-3.6-flash", "degraded": false }
```

Неизвестная валюта в `currency` игнорируется (ассистент ответит в базовой).

`source: "mock"` и `degraded: true` означают, что Gemini не ответил (в `reason`
указана причина), а чат отдал мок-ответ.

`GET /api/health` → `{ "ok": true, "gemini": true, "model": "…", "transport": "…", "mode": "gemini" }`

## Переменные окружения

Все — в `.env.example`. Основные: `GEMINI_API_KEY`, `GEMINI_MODEL`,
`GEMINI_TRANSPORT`, `GEMINI_TIMEOUT_MS`, `PORT`. Значения из `.env` не
переопределяют уже заданные переменные окружения процесса.
